# 생산자·소비자와 한정 버퍼 복습

> 생산 속도와 소비 속도가 다를 때 버퍼에서 생기는 문제와 `wait()`, `notify()`의 역할을 정리했다.

## 1. 기본 구조

생산자는 데이터를 만들고 소비자는 데이터를 처리한다. 두 역할의 속도를 직접 맞추기 어려우므로 중간에 버퍼를 둔다.

```text
생산자 → 한정 버퍼 → 소비자
```

- 생산자가 빠르면 버퍼가 가득 찬다.
- 소비자가 빠르면 버퍼가 비게 된다.

버퍼 크기가 제한되어 있어 한정 버퍼 문제라고도 볼 수 있다.

## 2. 즉시 실패하는 구현

```java
public synchronized void put(String data) {
    if (queue.size() == max) {
        return;
    }
    queue.offer(data);
}
```

큐가 가득 차면 데이터가 사라질 수 있다.

```java
public synchronized String take() {
    if (queue.isEmpty()) {
        return null;
    }
    return queue.poll();
}
```

소비자가 너무 빨리 실행되면 빈 결과를 받아야 한다.

## 3. 반복 확인의 한계

```text
while (queue.size() == max) {
    sleep(100);
}
```

공간이 생길 때까지 주기적으로 검사하는 방식은 다음 문제가 있다.

- 확인 간격만큼 반응이 늦다.
- 너무 자주 검사하면 CPU와 락 경쟁이 늘어난다.
- 조건이 바뀐 정확한 시점에 깨우지 못한다.

또한 락을 가진 채 기다리면 소비자가 같은 락을 얻지 못해 공간을 만들 수 없다.

## 4. `wait()`

```text
synchronized (this) {
    while (queue.size() == max) {
        wait();
    }
    queue.offer(data);
}
```

`wait()`를 호출하면 현재 스레드는 객체의 모니터 락을 반환하고 그 객체의 대기 집합으로 이동한다.

```text
락 반환
→ WAITING
→ 알림 수신
→ 다시 락 획득 경쟁
→ 조건 재확인
```

락을 소유한 `synchronized` 영역 안에서만 호출할 수 있다.

## 5. `notify()`와 `notifyAll()`

```java
notify();
```

같은 객체 대기 집합의 스레드 하나를 깨운다.

```java
notifyAll();
```

대기 중인 모든 스레드를 깨운다.

깨어난 스레드는 즉시 임계 영역을 실행하는 것이 아니라 락을 다시 얻어야 한다.

## 6. 조건은 `while`로 확인

```text
while (queue.isEmpty()) {
    wait();
}
```

깨어난 시점에 원하는 조건이 반드시 만족된다고 볼 수 없다.

- 다른 스레드가 먼저 데이터를 가져갈 수 있다.
- 진행할 수 없는 역할의 스레드가 깨울 수 있다.
- 예상하지 못한 깨어남을 고려해야 한다.

그래서 대기 후 조건을 다시 확인한다.

## 7. 생산자와 소비자의 흐름

### 생산자

```text
큐가 가득 찼는지 확인
→ 가득 차면 wait()
→ 공간이 있으면 데이터 추가
→ notify()
```

### 소비자

```text
큐가 비었는지 확인
→ 비었으면 wait()
→ 데이터가 있으면 제거
→ notify()
```

## 8. 하나의 대기 집합의 한계

기본 객체 대기 집합에는 생산자와 소비자가 함께 들어간다. `notify()`는 어떤 역할을 깨울지 지정하지 못한다.

큐가 가득 찬 상태에서 생산자를 깨우거나, 큐가 빈 상태에서 소비자를 깨우면 다시 기다려야 한다.

`notifyAll()`은 진행 가능성을 높이지만 필요 없는 스레드까지 모두 깨워 락 경쟁이 커진다. 이 문제는 다음 문서의 `Condition`으로 대기 공간을 분리해 개선한다.

## 핵심 정리

- 생산자와 소비자는 한정된 버퍼를 사이에 두고 서로 다른 속도로 동작한다.
- 즉시 실패 방식은 데이터 손실이나 빈 결과를 만들 수 있다.
- `wait()`는 락을 반환하고 객체의 대기 집합에서 기다린다.
- `notify()`는 하나를 깨우지만 역할을 선택할 수 없다.
- 대기 조건은 `while`로 다시 확인해야 한다.

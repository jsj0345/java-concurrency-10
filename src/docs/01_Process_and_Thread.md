# 프로세스와 스레드 복습

> 여러 작업이 동시에 움직이는 것처럼 보이는 이유부터 운영체제가 실제 실행 단위를 어떻게 다루는지 정리했다.

## 1. 멀티태스킹과 멀티프로세싱

CPU 코어가 하나뿐이어도 운영체제가 실행 시간을 짧게 나누어 여러 작업에 번갈아 배정하면 사용자는 작업들이 함께 진행되는 것처럼 느낀다.

```text
작업 A 실행
→ 작업 B 실행
→ 작업 C 실행
→ 다시 작업 A 실행
```

이런 실행 방식이 멀티태스킹이다. 코어가 여러 개라면 서로 다른 작업이 실제로 같은 시점에 실행될 수도 있다. 둘 이상의 CPU 코어를 활용하는 관점은 멀티프로세싱으로 이해했다.

- 멀티태스킹: 여러 작업에 CPU 시간을 나누어 배정
- 멀티프로세싱: 여러 코어로 병렬 실행 범위를 확대

## 2. 프로그램, 프로세스, 스레드

디스크에 있는 실행 파일은 아직 실행 중인 작업이 아니다. 운영체제가 프로그램을 실행하면 메모리와 시스템 자원을 가진 프로세스가 만들어진다.

프로세스는 서로 분리된 메모리 공간을 사용한다. 한 프로세스 내부에는 실제 작업 흐름을 담당하는 스레드가 하나 이상 존재한다.

```text
프로세스
├─ 코드와 공용 데이터
├─ 힙
├─ 스레드 1의 스택
└─ 스레드 2의 스택
```

같은 프로세스의 스레드는 힙과 코드 같은 자원을 공유하지만 각자 호출 스택을 가진다. 공유 덕분에 데이터를 전달하기 쉽지만 동시에 수정하면 동시성 문제가 생길 수 있다.

| 항목 | 같은 프로세스의 스레드 |
|---|---|
| 코드·힙·정적 데이터 | 공유 |
| 호출 스택 | 스레드마다 별도 |
| 실행 흐름 | 스레드마다 별도 |

## 3. 스케줄링

운영체제의 스케줄러는 실행 가능한 스레드 중 CPU를 사용할 대상을 선택한다.

스레드를 만들었다고 바로 실행되는 것은 아니다. 실행 준비가 끝난 뒤에도 실제 순서는 운영체제와 실행 환경에 따라 달라진다.

```text
스레드 생성 순서 ≠ 실제 실행 순서
```

우선순위는 스케줄러에 힌트를 제공할 뿐 정확한 실행 순서를 보장하지 않는다.

## 4. 컨텍스트 스위칭

CPU가 스레드 A를 멈추고 B를 실행하려면 A의 현재 상태를 기억해야 한다.

- 어느 명령까지 실행했는지
- 계산 중이던 값
- 레지스터 상태
- 스택 실행 위치

이 상태를 저장하고 다른 스레드의 상태를 불러오는 과정이 컨텍스트 스위칭이다. 멀티태스킹에 필요하지만 실제 업무 로직과 별개의 전환 비용이 든다.

스레드 수를 무조건 늘리면 항상 빨라지지 않는 이유 중 하나다.

## 핵심 정리

- 프로세스는 실행 중인 프로그램을 위한 독립된 작업 공간이다.
- 스레드는 프로세스 내부의 실제 실행 흐름이다.
- 같은 프로세스의 스레드는 여러 자원을 공유하고 스택은 따로 사용한다.
- 스케줄러가 CPU 사용 순서를 정하므로 실행 순서는 고정되지 않는다.
- 컨텍스트 스위칭에도 비용이 있다.
